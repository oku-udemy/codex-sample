# Frontend UI仕様

## 目的

Todo画面の構成、表示文言、操作、レスポンシブ挙動、アクセシビリティ上の現行動作を定義します。機能処理の詳細は[機能仕様](functional-spec.md)を参照してください。

## 対象範囲

`App`が描画する単一画面と、`styles.css`が定義する見た目を対象とします。複数ページ間のナビゲーションや共通デザインシステムは対象外です。

## 現行仕様

### 画面構成

画面は`main`内のTodoカード1つで構成します。

1. ヘッダー
   - アイブロウ: 「MY DAILY LIST」
   - 見出し: 「今日のTodo」
   - 補足: 「小さな予定を、ひとつずつ片づけよう。」
2. Todo追加フォーム
   - テキスト入力
   - 追加ボタン
3. エラーメッセージ（エラーがある場合）
4. 読み込み状態、空状態、またはTodo一覧
5. 完了件数（Todoが1件以上ある場合）

### 操作と表示文言

| 要素                 | 表示・ラベル                                                       | 操作           |
| -------------------- | ------------------------------------------------------------------ | -------------- |
| Todo入力             | プレースホルダー「新しいTodoを入力」、アクセシブル名「新しいTodo」 | 文字列を入力   |
| 追加ボタン           | 通常時「追加」、送信中「追加中…」                                  | フォームを送信 |
| 完了チェックボックス | Todoタイトルをアクセシブル名として持つ                             | 完了状態を反転 |
| 削除ボタン           | 表示「削除」、アクセシブル名「{Todoタイトル}を削除」               | 対象Todoを削除 |
| 読み込み状態         | 「読み込み中…」                                                    | 操作なし       |
| 空状態               | 「Todoはまだありません。」                                         | 操作なし       |
| 完了件数             | 「{完了件数} / {全件数} 件完了」                                   | 操作なし       |

完了済みTodoはタイトルを薄い色にし、取り消し線を付けます。

### キーボード操作

- 入力欄、追加ボタン、各チェックボックス、各削除ボタンには通常のTab順でフォーカスできます。
- 入力欄でEnterを押すとフォームを送信します。
- SpaceまたはEnterによるボタン操作と、Spaceによるチェックボックス操作はブラウザー標準動作に従います。
- 独自のキーボードショートカットはありません。

### アクセシビリティ

- Todoカードの`section`は`aria-labelledby="page-title"`で主見出しと関連付けます。
- 画面上は非表示の`label`により、Todo入力へ「新しいTodo」という名前を付けます。
- エラー領域は`role="alert"`を使用します。
- 読み込み表示は`aria-live="polite"`を使用します。
- 削除ボタンは対象Todoのタイトルを含む`aria-label`を持ちます。
- フォーカスは操作後に明示的に移動しません。
- 入力欄には視覚的なフォーカス表示があります。その他の要素はブラウザー既定のフォーカス表示に依存します。

### レスポンシブ表示

- 基本の最小表示幅は320pxです。
- Todoカードの最大幅は660pxで、画面幅に応じて縮小します。
- 520px以下では外側余白とカード内の左右余白を縮小します。
- 520px以下では追加フォームを縦並びにし、追加ボタンの最小高さを46pxにします。
- Todoタイトルは長い文字列を折り返します。

### 視覚表現

- 背景は淡色の放射グラデーション、Todoカードは半透明の白背景です。
- 主要操作には緑、削除操作には赤系の色を使用します。
- フォントはシステムフォントを優先し、見出しはセリフ体を使用します。

色値、余白、角丸などの具体値は`apps/frontend/src/styles.css`を正本とします。

## 改善候補

- 追加成功後のフォーカス位置を仕様化する。
- Todo更新・削除中の状態を支援技術へ通知する。
- 入力エラーを入力欄とプログラム的に関連付ける。
- 全操作要素に一貫した`:focus-visible`スタイルを定義する。
- 主要な色のコントラストを自動検査する。
- 画面状態ごとのビジュアルリグレッションテストを導入する。

これらは未実装であり、現行仕様には含めません。
