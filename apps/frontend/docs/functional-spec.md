# Frontend機能仕様

## 目的

Todo画面が利用者に提供する機能と、各操作に対する画面状態の変化を定義します。HTTPの詳細は[API連携仕様](api-integration.md)、表示上の詳細は[UI仕様](ui-spec.md)を正本とします。

## 対象範囲

- Todo一覧の初期取得
- Todoの追加
- Todoの完了状態の切り替え
- Todoの削除
- 読み込み中、保存中、空状態、エラーの表示

認証、Todoの編集、並べ替え、絞り込み、ページング、Frontendでの永続化は対象外です。

## 現行仕様

### 初期表示と一覧取得

1. 画面のマウント時にTodo一覧を1回取得します。
2. 取得が完了するまでは「読み込み中…」を表示します。
3. 取得成功時は、受信した順序でTodoを表示します。
4. 取得結果が0件の場合は「Todoはまだありません。」を表示します。
5. 取得失敗時はエラーメッセージを表示し、読み込み状態を終了します。
6. コンポーネントがアンマウントされた後は、完了した初期取得によるstate更新を行いません。ただし通信自体は中断しません。

### Todoの追加

1. 入力欄の前後空白を除いた文字列をタイトルとして扱います。
2. 空文字列または空白だけの場合は送信せず、追加ボタンを無効化します。
3. 送信中は追加ボタンを無効化し、ラベルを「追加中…」へ変更します。
4. 追加開始時に、それ以前のエラー表示を消去します。
5. 追加成功時は、返却されたTodoを現在の一覧末尾へ追加し、入力欄を空にします。
6. 追加失敗時は一覧と入力値を維持し、エラーメッセージを表示します。
7. 成否にかかわらず、処理完了後に保存中状態を解除します。

### 完了状態の切り替え

1. チェックボックス操作時に、現在の`completed`を反転した値で更新を要求します。
2. 更新開始時に、それ以前のエラー表示を消去します。
3. 更新成功時は、同じ`id`のTodoをサーバー応答で置き換えます。
4. 更新失敗時は現在の一覧を維持し、エラーメッセージを表示します。
5. 更新中を示す表示や、重複操作を防ぐ無効化は行いません。

### Todoの削除

1. Todoごとの削除ボタンから削除を要求します。
2. 削除開始時に、それ以前のエラー表示を消去します。
3. 削除成功時は、同じ`id`のTodoを現在の一覧から除外します。
4. 最後のTodoを削除した場合は空状態を表示します。
5. 削除失敗時は現在の一覧を維持し、エラーメッセージを表示します。
6. 確認ダイアログ、削除中表示、取り消し機能はありません。

### 完了件数

- 読み込み完了後、Todoが1件以上ある場合だけフッターを表示します。
- `completed`が`true`の件数と全件数を「完了件数 / 全件数 件完了」の形式で表示します。

### エラー

- 一度に保持する画面エラーは1件です。
- Errorオブジェクトの場合はその`message`を表示します。
- Error以外の値が捕捉された場合は「予期しないエラーが発生しました。」を表示します。
- 再試行専用ボタンはありません。追加、更新、削除は同じ操作を再度行えますが、初期取得は画面の再読み込みが必要です。

## 状態一覧

| 状態           | 条件                    | 主な表示・操作                        |
| -------------- | ----------------------- | ------------------------------------- |
| 初期読み込み中 | `loading`が`true`       | 「読み込み中…」を表示                 |
| 空             | 読み込み済みかつ0件     | 「Todoはまだありません。」を表示      |
| 一覧表示       | 読み込み済みかつ1件以上 | 一覧と完了件数を表示                  |
| 追加中         | `saving`が`true`        | 追加ボタンを無効化し「追加中…」を表示 |
| エラーあり     | `error`が文字列         | `role="alert"`でメッセージを表示      |

エラー表示は、読み込み、空、一覧の各状態と同時に存在できます。

## 制約

- Todoの表示順はAPIの返却順および追加順であり、並べ替え規則はありません。
- 更新と削除では楽観的更新を行わず、成功応答後に画面へ反映します。
- 更新中と削除中は操作を無効化しないため、同じTodoへの要求が並行する可能性があります。
- 入力文字数など、Frontend独自の上限検証はありません。

## 改善候補

- 初期取得の再試行操作を提供する。
- 更新・削除中の重複操作を抑止し、対象Todoへ進行状態を表示する。
- 通信を中断できるよう`AbortController`を利用する。
- 削除確認または取り消し機能を提供する。
- 並行要求の応答順による表示の逆転を防ぐ。

これらは未実装であり、現行仕様には含めません。
