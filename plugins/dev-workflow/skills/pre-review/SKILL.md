# レビュー前に差分を検査する

レビュー担当者の観点で実際の差分と検証結果を確認し、修正すべき問題と残余リスクを明確にする。

## 進め方

1. 差分、対応要件、計画ファイル、適用される `AGENTS.md`、関連するAPI・設計文書を読む。Git差分が取得できない場合は、利用者が指定した変更ファイルや比較資料を対象にする。対象を特定できなければ、推測でレビューせず不足している入力を報告する。
2. 仕様違反、論理不具合、入力検証、エラー処理、セキュリティ、互換性、データ損失、並行性、アクセシビリティを変更内容に応じて確認する。
3. テストが公開動作と異常系を十分に守るか、変更していないコードの主張をしていないかを確認する。
4. 実装と文書・設定・サンプルが同期しているか、秘密情報やローカル専用値が含まれていないかを確認する。
5. 利用可能な検証コマンドを実行し、失敗が今回の変更に起因するかを切り分ける。

## 報告

最初に、実際に修正すべき所見を重大度順で示す。各所見には、場所、再現または影響、修正が必要な理由を含める。同じ原因の指摘はまとめる。

所見がなければ「重大な所見なし」と明記し、確認した範囲、実行した検証、未検証のリスクを短く示す。外部のレビュー依頼やPR操作は、明示的に依頼された場合だけ行う。

## 完了条件

- すべての所見が差分または検証結果の具体的な根拠を持つ。
- スタイルの好みより、正しさ、要件、回帰、運用上の危険を優先している。
- 実行していない検証を成功したものとして扱っていない。
