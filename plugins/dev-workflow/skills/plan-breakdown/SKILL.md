# 要件を作業へ分解する

確定した `docs/requirements/system/` と現行コードを根拠に、レビュー可能な大きさのチケット案をMarkdownで作る。

## 進め方

1. 対象の要件ID、受け入れ条件、対象外、未解決事項を確認する。未確定事項を実装作業として確定しない。
2. コードと設計書を調べ、frontend、backend、API、文書、テストへの影響を特定する。
3. 独立して検証・レビューできる単位に分ける。必要なら調査や設計判断を実装と分ける。
4. 各作業に目的、対応要件ID、範囲、対象外、依存関係、受け入れ条件、検証方法、主なリスクを記載する。
5. 依存順、並行実施できる範囲、要件に含まれない作業を示す。

チケット案は [assets/ticket-draft-template.md](assets/ticket-draft-template.md) を基準に、`docs/plans/drafts/<作業ID>.md` または利用者が指定した場所へ保存する。実装を開始するときは、選択した案から`build-with-plan`が`docs/plans/<作業ID>.md`を作る。外部サービスへの登録や担当者・優先度の確定は、明示的に依頼された場合だけ行う。

## 完了条件

- 各受け入れ条件が少なくとも1つの作業に対応し、重複や欠落が説明されている。
- 各作業を単独で完了判定でき、依存関係と検証方法が明確である。
- 要件から導けない仕様を事実として追加していない。

出力時はチケット案の一覧、依存順、確認が必要な判断を報告する。
