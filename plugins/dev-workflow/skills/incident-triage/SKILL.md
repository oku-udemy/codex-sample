# 障害を切り分ける

観測事実と仮説を分け、影響の抑制、原因究明、恒久対応に必要な情報をまとめる。

## 入力

- 利用者が提供した症状、時刻、再現手順、ログファイル、スクリーンショット
- リポジトリ内のローカルログ、コード、テスト、設定例、Git履歴、`docs/runbooks/`

秘密情報や個人情報を報告へ転載しない。外部システム、本番環境、ログ基盤の検索や変更は、利用可能な接続と明示的な依頼がある場合だけ行う。

## 進め方

1. 発生時刻、影響範囲、再現性、直前の変更、期待動作を確認する。不足していても安全なローカル調査は進め、必要な追加情報を列挙する。
2. ログの相関ID、エラー、時間順序を整理し、コード経路と最近の差分に対応づける。
3. 観測事実、仮説、反証、未確認事項を分ける。単一のログ行だけで根本原因を断定しない。
4. 安全に実行できるテストやローカル再現で仮説を絞る。診断依頼だけなら修正は実装しない。
5. 影響を抑える選択肢、追加調査、修正候補、回帰テスト、文書化すべき事項を提示する。破壊的操作や本番変更は実行前に明示的な承認を得る。

報告には [assets/incident-report-template.md](assets/incident-report-template.md) を使える。

## 完了条件

- 影響、タイムライン、事実、仮説、証拠、次の行動が区別されている。
- 確度と不足情報が明示され、原因未確定の場合に断定していない。
- 実施した診断と、実施していない本番・外部操作が明確である。
