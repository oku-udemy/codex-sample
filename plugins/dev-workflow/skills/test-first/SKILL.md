# テストを先に作る

新しい振る舞いを観測するテストを先に追加し、実装前の失敗と実装後の成功を検証できる状態にする。

## 進め方

1. 要件ID、受け入れ条件、計画、既存テスト、変更箇所に適用される `AGENTS.md` を確認する。
2. 正常系、異常系、境界値から、変更のリスクに見合うテストケースを選ぶ。実装詳細ではなく公開動作を検証する。
3. 既存のテスト構成に合わせ、最小限のテストコードを追加する。テスト名または近接する説明に要件IDを関連づける。
4. 対象workspaceのテストを実行し、新しいテストが期待した理由で失敗することを確認する。環境障害や既存不具合による失敗と区別する。
5. 実装も依頼されている場合は、必要最小限の変更で成功させる。テスト作成だけの依頼なら実装は変更しない。
6. 対象テストを再実行し、影響範囲に応じて `npm test`、`npm run lint`、`npm run build`、必要なら `npm run test:e2e` まで広げる。

スキップ、常に成功するアサーション、実装と同じロジックの再実装、共有状態に依存する不安定なテストは避ける。

## 完了条件

- 受け入れ条件とテストケースの対応が説明できる。
- 実装前の失敗理由と実装後または現時点の結果を報告できる。
- 実行できなかった検証と理由が明記されている。
