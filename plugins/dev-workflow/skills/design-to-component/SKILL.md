# デザインをコンポーネントへ変換する

受領資料の意図を保ちつつ、既存のReactコンポーネント、画面設計、デザイントークンへ適合させる。

## 進め方

1. 原本、抽出物、画像や表、対応する要件IDを確認する。読めない表現や状態は推測せず確認事項にする。
2. `apps/frontend/docs/` と既存コンポーネントを調査し、再利用できる要素、追加が必要な要素、画面固有部分を分類する。
3. 表示状態、操作、エラー、空状態、ローディング、レスポンシブ挙動、アクセシビリティを整理する。
4. コンポーネント境界、props、状態、イベント、APIデータとの対応を設計する。受領資料にない複雑な抽象化は加えない。
5. 実装を依頼されている場合は、小さなプロトタイプまたは本番コードを作り、既存のスタイル規約とテスト方法で検証する。依頼が設計だけならコードは変更しない。
6. デザインと実装の差異、代替表現、未確認事項を記録し、必要なfrontend文書を更新する。

整理用には [assets/component-mapping-template.md](assets/component-mapping-template.md) を使える。

## 完了条件

- デザイン上の主要要素と状態が、既存または新規コンポーネントへ追跡できる。
- キーボード操作、ラベル、フォーカス、コントラストなど該当するアクセシビリティ要件を扱っている。
- 原本にない仕様を断定せず、差異と確認事項を利用者へ示している。
