# 文書を変更内容に同期する

差分と実際の動作を根拠に、最も近い保守対象文書を必要な範囲だけ更新する。

## 進め方

1. 作業差分、計画、要件ID、変更箇所に適用される `AGENTS.md` を確認する。
2. 更新対象を特定する。横断的な契約はルートの `docs/`、アプリ固有の設計は各アプリの `docs/`、E2Eは `e2e/docs/` を優先する。
3. 現在の実装、利用者に見える動作、設定、制約、検証方法を反映する。コードから確認できない意図は推測しない。
4. `docs/requirements/business/<案件名>/source/` の原本は変更しない。抽出物の再生成が必要な場合は `extracted/` を更新し、出典と差異を記録する。
5. 確定したシステム要件の解釈や範囲が変わる場合は、直接確定せず、変更案、理由、影響する要件IDを提示する。
6. リリース記録を依頼された場合は、対象期間の計画・差分・検証結果から `docs/releases/<YYYY-MM-DD>-<version-or-name>.md` の下書きを作る。
7. リンク、コマンド、ファイルパスが現状と一致するか確認する。

リリース記録には [assets/release-note-template.md](assets/release-note-template.md) を使う。

## 完了条件

- 変更された公開動作、API、設定、運用手順に対応する文書が更新されている。
- 原本と確定要件の境界が保たれ、未確認の変更案が明示されている。
- 更新不要と判断した文書がある場合、その理由を説明できる。
