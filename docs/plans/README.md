# 作業計画

複数アプリ、API契約、データ移行、運用変更など、途中判断と検証状況を追跡する必要がある変更に使用します。局所的で明確な修正では計画文書を必須にしません。

要件から分解した未着手のチケット案は`drafts/<作業ID>.md`へ置きます。実装を開始するときは、Pluginの`build-with-plan/assets/plan-template.md`を基準に`<作業ID>.md`をこのディレクトリ直下へ作り、作業中にチェック状況と決定を更新します。完了後も結果と残課題を残し、単なる事前メモで終わらせません。

外部チケットIDがない場合、作業IDには目的を表す短い`kebab-case`を使います。チケット案と実装計画を同じパスへ置かず、実装開始時に必要な内容を引き継ぎます。
