# システム要件

## 文書情報

- 状態: approved
- 対象: 開発フロー検証用Todoサンプル
- 最終確認日: 2026-10-04

## 目的

利用者がブラウザーで簡単なTodoを管理でき、開発者がFrontend、Backend、テスト、文書を一貫した手順で変更・検証できるサンプルを提供します。

## 機能要件

| ID       | 要件                 | 受け入れ条件                                                     |
| -------- | -------------------- | ---------------------------------------------------------------- |
| SR-F-001 | Todo一覧を表示できる | 画面を開くとAPIから取得したTodoが返却順に表示される              |
| SR-F-002 | Todoを追加できる     | 空白ではないタイトルを送信すると未完了Todoが一覧末尾に表示される |
| SR-F-003 | 完了状態を変更できる | チェック操作後、成功応答の状態が画面と完了件数へ反映される       |
| SR-F-004 | Todoを削除できる     | 削除成功後に対象Todoが一覧から消える                             |
| SR-F-005 | 通信失敗を通知できる | APIエラー時に利用者が認識できるエラーメッセージを表示する        |

## 非機能要件

| ID        | 要件                                | 受け入れ条件                                                                |
| --------- | ----------------------------------- | --------------------------------------------------------------------------- |
| SR-NF-001 | 基本操作をキーボードで行える        | 入力、追加、完了切替、削除へ通常のTab順で到達して操作できる                 |
| SR-NF-002 | 320px以上の画面幅で主要操作を行える | 入力と操作要素が利用不能になる横方向の欠落を生じない                        |
| SR-NF-003 | 開発環境を再現できる                | Node.js/npmまたは`docker compose up --build`でFrontendとBackendを起動できる |
| SR-NF-004 | 変更を自動検証できる                | Vitest、Playwright、ESLint、TypeScript、Prettierの標準コマンドが定義される  |

## 制約と対象外

- TodoはBackendプロセスのメモリ内だけに保存し、再起動後の永続性を保証しません。
- 認証、認可、複数利用者、期日、編集、並べ替え、検索、ページングは対象外です。
- FrontendとBackendは型を直接共有せず、HTTP契約を介して連携します。
- CI、課題管理、集中ログ基盤、外部MCPは接続先が決まるまで対象外です。
