# 要件管理

## 要件の流れ

1. Word／Excelを案件ディレクトリの`source/`へ原本のまま保存する。
2. 表、見出し、注記を保持しながら`extracted/`へMarkdownとして正規化する。
3. 不明点、矛盾、欠落、仮定を抽出文書内で明示し、原本へ推測を書き戻さない。
4. 確認済みの内容を`system/<案件名>.md`へ一意な要件IDと受け入れ条件付きで反映する。
5. 設計、実装、テストから要件IDを参照し、変更時の影響を追跡する。

## 状態

- `draft`: 未確認または検討中。
- `approved`: 実装の基準として合意済み。
- `superseded`: 後続要件で置換済み。削除せず置換先を示す。
- `rejected`: 採用しない判断が確定。理由を残す。

要件の意味を変える変更は、システム要件を直接「正しいはずの内容」へ直すのではなく、根拠、変更理由、影響範囲を記録してから反映します。
