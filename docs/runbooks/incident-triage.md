# 障害・不具合の切り分けRunbook

## 目的

提供されたログ、ローカルログ、ブラウザー情報から事実を集め、再現条件、影響範囲、暫定対応、恒久対応を分離して記録します。未選定の外部ログ基盤や課題管理への接続は前提にしません。

## 手順

1. 発生日時、環境、利用者操作、期待結果、実際の結果を記録する。
2. 秘密情報や個人情報を除いたログ、HTTP status、エラーコード、画面画像を収集する。
3. Frontend、HTTP/CORS、Backend、テスト環境のどこで差異が初めて現れるか絞る。
4. 現行コードと要件に照らし、仕様、設定誤り、不具合、未確認のいずれかを区別する。
5. 可能なら最小の再現テストを追加し、修正前に失敗することを確認する。
6. 回避策と恒久修正を分け、影響が大きい場合は`docs/plans/`へ計画を作る。

## 記録テンプレート

```markdown
# 事象名

- 発生日時・タイムゾーン:
- 環境:
- 影響:
- 状態: investigating | mitigated | resolved

## 再現手順と証拠

## タイムライン

## 原因

## 暫定対応

## 恒久対応と回帰テスト

## 残課題
```

原因が未確定の段階では推測を断定せず、「確認済みの事実」と「仮説」を分けます。
