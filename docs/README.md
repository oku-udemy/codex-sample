# プロジェクト文書

このディレクトリは、Todoサンプルのリポジトリ横断情報と開発フローの正本です。コードから確認できる事実だけを重複して列挙せず、判断、契約、受け入れ条件、運用手順を記録します。

## 文書体系

| 領域         | 内容                                          | 主な正本                                |
| ------------ | --------------------------------------------- | --------------------------------------- |
| 業務要件     | 受領したWord／Excel原本と、その正規化Markdown | `requirements/business/`                |
| システム要件 | 実装可能な要件、対象外、受け入れ条件          | `requirements/system/`                  |
| 用語         | プロジェクト内の語の意味                      | `requirements/glossary.md`              |
| 横断設計     | システム境界、データフロー、重要判断          | `architecture/`                         |
| API          | FrontendとBackend間のHTTP契約                 | `api/`、`apps/backend/docs/api-spec.md` |
| 作業計画     | 複数領域にまたがる変更の計画と検証結果        | `plans/`                                |
| 運用         | ローカル開発、障害切り分け                    | `runbooks/`                             |
| リリース     | 変更履歴とリリース確認                        | `releases/`                             |

アプリ固有の詳細は`apps/frontend/docs/`と`apps/backend/docs/`、E2E方針は`e2e/docs/`を参照します。

## 更新ルール

文書には「現行仕様」「決定」「提案」「未決事項」を混在させず、見出しや状態で区別します。実装変更で現行仕様が変わる場合は同じ変更単位で文書を更新します。業務原本は不変とし、解釈変更は抽出文書やシステム要件へ履歴が分かる形で反映します。
