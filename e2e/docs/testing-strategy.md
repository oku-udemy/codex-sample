# E2Eテスト戦略

## 役割

E2Eはアプリ単位のテストでは検出しにくい、ブラウザー操作、FrontendとBackendの接続、主要導線を確認します。全入力分岐はFrontendコンポーネントテストとBackend APIテストへ置き、E2Eは少数の高価値シナリオへ限定します。

## 現行シナリオ

| シナリオ           | 検証内容                                 |
| ------------------ | ---------------------------------------- |
| Todo管理の主要導線 | 追加、一覧反映、完了切替、完了表示、削除 |
| 初期取得失敗       | APIの500応答を画面のalertとして表示      |

## 作成規約

- ロール、ラベル、表示文言を優先し、CSSクラスやDOM階層だけに依存しません。
- 固定時間のsleepを使わず、`expect`による状態待機を使います。
- テスト間でTodoの存在や実行順を共有しません。
- ネットワーク異常は`page.route`で対象要求だけを制御します。
- 日時を使う場合でも、表示値へ厳密な時刻を期待しません。

## 設定と成果物

`fullyParallel`はfalseです。CIでは最大2回再試行し、最初の再試行時にtraceを取得します。HTML report、trace、スクリーンショットなどの生成物は調査用であり、通常はコミットしません。

## 追加判断

利用者の主要導線、Frontend・Backend契約、ブラウザー固有の挙動、重要なキーボード操作、モバイルviewportでの操作性を変更する場合にE2E追加を検討します。単純な表示分岐やAPI入力異常は、より速い下位テストで検証します。
